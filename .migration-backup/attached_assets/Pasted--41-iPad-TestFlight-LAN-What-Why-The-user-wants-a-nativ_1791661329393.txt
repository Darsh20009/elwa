#41 - بناء تطبيق iPad لإلوة وتجهيزه لـTestFlight عبر LAN What & Why The user wants a native Flutter iPad companion for Elwa's existing POS, using Blackrose's Flutter/Codemagic setup only as a technical reference. Start with LAN printing because the browser cannot directly reach generic thermal printers. The first release must print receipts over the local network and include a Codemagic workflow that can build and submit the iOS app to TestFlight. Done looks like A separate Flutter iPad project exists in the migrated workspace and matches Elwa's existing logo, colors, fonts, and visual identity. Staff can connect to a supported LAN thermal printer using a configurable IP address and port, run a connection test, and print a real POS receipt from the app. The iOS app requests local-network access with a clear permission explanation and reports connection/printing errors rather than claiming success. The app has separate LAN, Bluetooth, and wired-USB transport paths where the Epton printer model exposes an iOS-compatible protocol or vendor SDK. Unsupported transports are clearly identified rather than simulated. The printing transport and command set are verified against the user's actual Epton printer before describing the device as supported. Keep printer protocol/port configurable where appropriate; do not assume ESC/POS compatibility without a test. codemagic.yaml exists at the Git repository root and points to the iPad artifact, builds the iOS app on a macOS runner, and is configured for TestFlight signing/submission without committing credentials. The Elwa App Store provisioning profile supplied by the user is stored in Codemagic signing settings, not Git; the matching Apple Distribution certificate and App Store Connect integration are also configured there. The app builds successfully in Codemagic's workflow once the owner supplies Apple signing/API settings, and the TestFlight build is visible in App Store Connect. The web POS continues to run and its existing receipt/printing flow is not regressed. Out of scope Guaranteeing compatibility with every printer model or claiming zero errors without testing the actual Epton model and protocol. Any transport (USB, Bluetooth, or LAN) that the printer model does not expose through an iOS-compatible protocol or vendor SDK; report this as a hardware limitation and explain the verified alternative. Public App Store release, payments, or unrelated redesigns. Committing Apple private keys, certificates, provisioning profiles, passwords, or API keys to Git.
